# 金額不參與分流決策

資深客服說「退款金額超過 30,000 元一定要主管簽核」，直覺會想在分流時加一條金額門檻。我們刻意不做，改成**所有不可逆動作一律轉真人**，金額只當作記錄欄位輸出給人工參考。

## 為什麼

工單裡的金額是客戶自己打的字，不是系統值。用它當門檻等於讓客戶自己決定要不要送簽核：少寫一個零就繞過了。而且客戶提到的數字經常不是本次交易金額，可能是他記錯的團費、是求償金額、是兩筆扣款通知的差額。

真正的金額只有訂單系統知道，而訂單系統的 API 權限在專案開工時還沒下來。在拿不到權威金額之前，任何以金額為條件的規則都是把安全性建立在客戶的誠實上。

## 代價

不可逆動作全部轉真人，會讓自動處理率明顯偏低。這是誠實的低，不是失敗：在訂單 API 尚未接通的前提下，系統本來就無法安全地執行任何會動到訂單或金流的事。

## 這條規則要防的被改掉

未來有人看到自動處理率偏低，很自然會提議「小額的就自動處理吧」。這個 ADR 的存在就是為了讓那個提議必須先回答一個問題：那個金額是誰說的。
