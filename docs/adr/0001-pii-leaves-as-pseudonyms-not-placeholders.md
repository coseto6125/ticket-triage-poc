# 個資以假名而非佔位符離開本機

法務的限制是「客戶個資不得傳輸到未經評估與簽約的外部服務」，而分類要用外部 LLM。我們的解法是在本機抽取個資、換成**同型別的假值**（真實姓名換成另一個自然的姓名、手機號換成另一支格式合法的手機號），只讓假名化後的文字離開本機，回覆送出前再由程式把假值換回原值。

## 為什麼不用佔位符

直覺做法是換成 `<PII_NAME_1>` 這種佔位符。它更安全，但會傷到分類品質：模型看到「`<PII_NAME_1>` 您好，我想取消 `<PII_DATE_1>` 的行程」比看到一段自然的中文更難判斷語氣與訴求，而客訴性質正是靠語氣判斷的。假名保留了文字的自然度，同時讓外流的內容不對應到任何真實的人。

## 代價

假名必須與原值型別一致才有意義，所以抽取層必須連「這是姓名還是公司抬頭」都判斷正確。判斷錯了，假名會是錯的型別，回覆讀起來就會怪。這是我們接受的代價，換來的是分類品質不因為隱私保護而下降。

## 邊界的位置

假名對照表是行程內的區域變數，不寫檔、不進日誌、不進送出的請求。這讓「個資不出境」是結構上的保證，而不是紀律上的承諾：送給外部服務的資料結構裡沒有可以放原值的欄位。
